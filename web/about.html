Pharma Q&A: system overview

Question answering over the ClinicalTrials.gov API v2 and openFDA drug labels. Trial questions are answered through typed API tools. Label questions are answered by hybrid retrieval over 3,306 label-section chunks for 53 drugs. Every citation is validated in code against the retrieved evidence. Evaluated on a 30-question golden set.

01

Architecture

Request flow: entity resolution → routing → trial tools and/or label retrieval → generation → citation validation. Trial records are structured and queried through API tools. Labels are unstructured text and are retrieved by search.

Citation validation runs in code after generation. Every cited ID must match an evidence item passed to the generator; otherwise the response is converted to an abstain. Each request writes a JSON trace.

Components

Entity resolution

Brand and generic names come from a synonym map built from label metadata (Keytruda → pembrolizumab). The LLM extracts mentions only when the map finds none. Unresolved mentions are kept and marked unresolved.

Router Haiku 5.5

Structured output: trials | label | both | out_of_scope, plus label_query, the label part of the question rewritten as a standalone search query.

Trial tools ClinicalTrials.gov

Typed search_trials, count_trials and get_trial. Pydantic validates arguments before any request. Counts come from the registry's totalCount, not the model.

Label RAG openFDA

One prescription label per drug, chunked by label section. BM25 and bge-small embeddings run in parallel, merged with Reciprocal Rank Fusion and filtered to the resolved drug. Top 5 go to the generator.

Generator Sonnet 5.5

Returns a Pydantic DraftAnswer: text with inline [evidence-id] markers, a citation list, an abstain flag and an abstain reason. No free-text parsing.

API, tracing, hosting

FastAPI POST /ask with a per-IP rate limit. A JSON trace per request holds entities, route, tool calls, retrieved IDs, the draft, tokens, latency and cost. Runs in Docker on Cloud Run (Terraform), scaling 0 → 2.

Trace of eval question q01, after-fix run. Total 9.7 s and $0.022, of which the generator call is 6.1 s and $0.017.

  1. Question
    "Which Phase 3 trials is Keytruda being tested in for lung cancer?"
  2. Resolve entitiessynonym map · no LLM call
    Keytruda → pembrolizumab
  3. RouteHaiku 5.5 · 2.2 s · $0.0001
    kind = "trials" label_query = null
  4. Plan and run toolsSonnet 5.5 · 1.3 s · $0.005

    Arguments are validated with Pydantic before the HTTP request. Invalid values (NCT ID pattern, unknown phase, limit > 50) are rejected.

  5. GenerateSonnet 5.5 · 6.1 s · $0.017
    "NCT02142738, Pembrolizumab vs platinum-based chemotherapies in metastatic NSCLC (KEYNOTE-024), Phase 3, Completed [trial:NCT02142738]. …"
  6. Check citations, in codeno LLM call

    All 10 cited IDs are in the evidence set, so the response returns 10 citations linking to ClinicalTrials.gov. Any cited ID not in the evidence set converts the response to an abstain.

How each metric is scored

Routing · entities

Exact match against expected_route and the expected set of generic names.

Retrieval recall@5

Each expected source type (trial, count, label section) has a hit in the top 5 of that type.

Citation validity

Measured on the model's draft and on the final response. The final value is 100% by construction.

Answer correctness

Every required fact, with accepted alternatives ("MTC" or "medullary thyroid"), appears in the answer.

Baseline failure and fix

Baseline: 24 of 26 answerable questions correct; q16 and q25 failed. Cause in both traces: label retrieval used the full question as the query. Fix: the router returns label_query, a label-only query used for retrieval. Result: 26 of 26; latency and cost unchanged.

06

Build steps

Order of work and the finding from each step. The eval set was written before the LLM components.

  1. 01Probe both APIs filter.phase does not exist in ClinicalTrials.gov v2. Phase filtering uses aggFilters=phase:2 3.
  2. 02Ingest labels, build synonyms 53 drugs, 3,306 section chunks. Tecentriq and Tagrisso have no harmonized openFDA metadata, so they are matched on product data text.
  3. 03Write the golden set Before the LLM components. The Ozempic label uses "MTC", not "medullary thyroid carcinoma"; the check accepts either form.
  4. 04Hybrid retrieval Recall@5 14/14 with correct entities. Cross-encoder reranker: 13/14; disabled by default.
  5. 05Pipeline and unit tests 18 offline tests with a scripted fake LLM: citation check, abstain paths, argument validation. No API calls.
  6. 06Baseline eval First run segfaulted: concurrent inference on the embedding model. FastAPI's threadpool triggers the same fault. Inference is serialized with a lock. Baseline: 92.3% correctness.
  7. 07One fix, rerun, repeat label_query → 100% correctness. A repeat run measures run-to-run variance. Each run is saved with per-question traces.
  8. 08Ship Docker image, then Cloud Run via Terraform: API key in Secret Manager, 0–2 instances, budget alert, infra/deploy.sh.
07

Limitations and next steps

The after-fix runs score 100% on most metrics, so the 30-question set no longer separates good from bad changes. Each limitation below maps to a production change.

Eval set size

30 questions at ceiling. Next set: misspellings, multi-drug questions, dosing detail, ambiguous label text.

String-match grading

Deterministic, but a correct paraphrase can fail. Next: an LLM judge calibrated against expert labels.

Synonym map

No fuzzy matching and no condition hierarchy, so "NSCLC" is not treated as part of "lung cancer".

Snapshot data

Trial responses are cached for repeatable evals, as of 2026-10-25. One label per drug; no reindexing.

At production scale

Curated ontology

MeSH, RxNorm or an in-house drug and disease taxonomy, for drugs and conditions, including hierarchy in trial search.

Managed hybrid index

Azure AI Search over the full label corpus, with reindexing keyed on label version and freshness shown per citation.

Eval as a CI gate

A curator-labelled golden set, a calibrated judge, repeated runs for variance, and user feedback added to the set.
